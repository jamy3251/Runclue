# RunClue Web

RunClue 앱의 기능과 사용자 흐름을 웹에서 확인할 수 있도록 만든 정적 웹 프로토타입입니다.

## 실행

```bash
cd runclue-web
python3 -m http.server 4173
```

브라우저에서 `http://localhost:4173/`을 엽니다.

## 구현 기준

본 웹 구현은 현재 앱에서 구동되는 기능과 사용자 흐름을 기준으로 한다.

- 웹은 현재 앱의 주요 사용 흐름인 클루 발견, 클루 만들기, 클루 참여, 마이페이지를 동일하게 제공한다.
- 웹 초기 진입 화면에는 서비스 랜딩 영역과 로그인/회원가입 영역을 함께 제공한다.
- 로그인 이후에는 앱의 실제 사용 화면처럼 클루를 탐색하고, 만들고, 참여할 수 있어야 한다.
- 관리자 기능은 일반 사용자 흐름과 분리된 웹 전용 관리 화면으로 제공한다.
- 전체 UX는 현재 앱의 구조와 톤을 따르되, 웹 레이아웃에 맞게 재배치한다.

## 페이지 구성

| 경로 | 설명 | 접근 권한 |
|------|------|-----------|
| `/` | 랜딩 + 로그인/회원가입 통합 화면 | 비로그인 사용자 |
| `/home` | 클루 탐색/발견 화면 | 로그인 사용자 |
| `/create` | 클루 만들기 화면 | 로그인 사용자 |
| `/join` | 클루 참여 화면 | 로그인 사용자 |
| `/mypage` | 회원정보 수정 화면 | 로그인 사용자 |
| `/admin` | 클루 승인 관리 화면 | 관리자 |

현재 정적 프로토타입은 별도 백엔드 라우팅 없이 `index.html`에서 화면을 전환한다. 메뉴를 누르면 브라우저 주소는 위 경로처럼 변경되지만, 단순 정적 서버에서는 새로고침 또는 직접 경로 진입 시 서버 fallback 설정이 필요하다.

## 인증 및 권한

- Supabase Auth 기반으로 로그인/회원가입을 처리한다.
- Supabase 세션을 기준으로 로그인 상태를 유지한다.
- 로그인 후 앱과 같은 Supabase 프로젝트의 `profiles`, `clues`, `participations` 테이블을 조회한다.
- 비로그인 사용자가 보호된 화면에 접근하면 `/` 화면을 보여준다.
- 이미 로그인한 사용자가 `/`에 접근하면 `/home` 화면으로 이동한다.
- `/admin`은 `profiles.role = 'admin'` 기준으로 접근을 제한한다.
- 관리자 승인/반려는 실제 `clues.status` 값을 업데이트한다.

## 사용자 역할

```ts
role: 'user' | 'moderator' | 'admin'
```

- `user`: 일반 사용자
- `moderator`: 운영 보조 역할
- `admin`: 클루 승인/반려 가능 관리자

## 주요 화면 흐름

### 초기 진입

1. 사용자가 `/`에 접근한다.
2. 화면에는 서비스 랜딩 콘텐츠와 로그인/회원가입 폼이 함께 표시된다.
3. 사용자는 로그인 또는 회원가입을 진행한다.
4. 인증 완료 시 `/home`으로 이동한다.

### 로그인 이후 사용자 흐름

1. 사용자는 `/home`에서 클루를 탐색한다.
2. 사용자는 `/create`에서 새로운 클루를 만들 수 있다.
3. 생성된 클루는 즉시 공개되지 않고 관리자 승인 대기 상태가 된다.
4. 관리자가 승인한 클루만 다른 사용자에게 노출된다.
5. 사용자는 `/join`에서 승인된 클루에 참여할 수 있다.
6. 사용자는 `/mypage`에서 자신의 회원정보를 수정할 수 있다.

## 클루 상태

```ts
status: 'draft' | 'pending_approval' | 'approved' | 'active' | 'completed' | 'rejected' | 'suspended'
```

| 상태 | 설명 |
|------|------|
| `pending_approval` / `draft` | 사용자가 클루를 생성한 직후, 관리자 승인 대기 상태 |
| `active` / `approved` | 일반 사용자에게 노출 및 참여 가능한 상태 |
| `rejected` | 관리자가 반려한 상태, 일반 사용자에게 노출하지 않음 |

## 클루 만들기

- 경로: `/create`
- 접근 권한: 로그인 사용자
- 생성된 클루의 기본 상태는 `pending_approval`이다.
- `pending_approval` 상태의 클루는 일반 사용자에게 노출되지 않는다.
- 관리자가 승인해야 `/home` 또는 `/join`에서 확인할 수 있다.

### 입력 항목 예시

- 클루 제목
- 클루 설명
- 카테고리
- 장소
- 날짜/시간
- 모집 인원
- 이미지
- 참여 조건 또는 안내사항

## 클루 탐색

- 경로: `/home`
- 접근 권한: 로그인 사용자
- `active` 또는 `approved` 상태의 클루만 노출한다.
- 앱의 클루 발견 화면과 유사한 흐름으로 구성한다.
- 클루 상세 정보 확인 및 참여 흐름으로 이어질 수 있어야 한다.

## 클루 참여

- 경로: `/join`
- 접근 권한: 로그인 사용자
- `active` 또는 `approved` 상태의 클루만 참여 가능하다.
- 모집 인원이 가득 찬 경우 참여할 수 없다.
- 이미 참여한 클루에는 중복 참여할 수 없다.
- 참여 완료 후 참여 상태가 화면에 반영되어야 한다.

## 마이페이지

- 경로: `/mypage`
- 접근 권한: 로그인 사용자
- 사용자는 자신의 회원정보를 확인하고 수정할 수 있다.
- 앱의 마이페이지 흐름과 동일한 기준으로 구성한다.

### 수정 가능 항목 예시

- 닉네임
- 프로필 이미지
- 자기소개
- 관심 카테고리
- 기타 앱에서 사용 중인 사용자 프로필 정보

이메일, 비밀번호 변경은 Supabase Auth 정책에 맞춰 별도 처리한다.

## 관리자 페이지

- 경로: `/admin`
- 접근 권한: 관리자 전용
- 관리자는 사용자가 생성한 클루 중 `pending` 상태의 클루를 확인할 수 있다.
- 관리자는 클루를 승인하거나 반려할 수 있다.
- 승인된 클루는 `approved` 상태가 되어 일반 사용자 화면에 노출된다.
- 반려된 클루는 `rejected` 상태가 되며 일반 사용자 화면에 노출되지 않는다.

## 인증 연동

- Supabase 프로젝트: 앱의 `app/lib/config/supabase_config.dart`와 같은 URL/anon key 사용
- 로그인: `supabase.auth.signInWithPassword`
- 회원가입: `supabase.auth.signUp`, `nickname`을 user metadata로 전달
- 비밀번호 재설정: `supabase.auth.resetPasswordForEmail`

Supabase 프로젝트에서 이메일 확인이 켜져 있으면 `signUp` 후 즉시 세션이 내려오지 않고 로그인도 막힙니다.
닉네임/아이디/비밀번호 입력 즉시 가입 및 로그인을 원하면 Supabase Dashboard에서 Auth email confirmation을 꺼야 합니다.
이미 미확인 상태로 만들어진 테스트 계정은 `supabase_auth_no_email_confirm.sql`을 SQL Editor에서 실행해 확인 처리할 수 있습니다.

소셜 로그인은 Supabase Provider와 Redirect URL 설정이 맞아야 실제 배포 도메인에서 동작합니다.
